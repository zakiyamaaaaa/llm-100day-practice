# Day 63: RAGをTool化

## 学習テーマ

Production RAG v1の検索処理を、Agentから呼び出せる`search_documents` Toolとして登録した。

新しい検索アルゴリズムは作らず、既存の次の処理をToolのhandlerから再利用した。

```text
search_documents
  ↓
BM25・Vector検索
  ↓
RRF
  ↓
Reranker
  ↓
source付き検索結果
```

## Tool化した検索結果

Toolは最終的な自然文の回答を生成せず、回答に使える候補文書を返す。

```json
{
  "query": "様式第4号の提出先はどこですか？",
  "results": [
    {
      "source": "doc_2",
      "title": "社外PC持出許可申請書",
      "text": "社外PC持出許可申請書（様式第4号）の提出先は、セキュリティチームです。",
      "relevance_score": 1.0
    }
  ],
  "sources": ["doc_2"]
}
```

## sourceの役割

`source`は、検索結果の本文がどの文書から取得されたかを表す。

```text
source: doc_2
```

これは「この情報の出典は`doc_2`」という意味である。
後から引用元を追跡したり、LLMがContextに存在しない文書を引用していないか検証したりできる。

## Rerankerの採点基準

今回のRerankerは、BM25やベクトル検索の数式で再計算しているのではなく、LLMに質問と候補本文を直接比較させている。

主な基準は次の通り。

1. 質問に直接答えられる情報があるか
2. 質問と文書の内容が意味的に関連しているか
3. 文書に書かれていない情報を推測していないか

`relevance_score`は0.0〜1.0の範囲で、`reason`には評価理由を保存する。

```text
BM25       = 単語の一致度を数式で評価
Vector検索 = ベクトル間の意味的な近さを評価
Reranker   = LLMが質問と候補本文を読んで関連性を評価
```

今回の質問では、`doc_2`が様式第4号の提出先を直接説明しているため1.00となり、様式第1号・第9号を説明する`doc_1`・`doc_3`は0.00となった。

ただし、Rerankerのスコアは固定された数学式ではなくLLMの判断である。そのため、実務ではReranker前後のHit@1やMRRを評価する必要がある。

## 検索候補と最終引用の違い

`top_k=3`で検索したため、`doc_2`、`doc_3`、`doc_1`の3件がTool結果に含まれた。

```text
search_documents = 候補文書を返す
Context Builder  = 回答に使う文書を選ぶ
LLM              = 選択された文書を根拠に回答する
```

したがって、Tool結果の`sources`に候補文書がすべて含まれていても、それが最終回答で実際に引用された文書一覧とは限らない。

## 実行結果

```text
[Tool実行結果]
status: success
tool_name: search_documents
query: 様式打４号の提出先はどこですか
sources: ['doc_2', 'doc_3', 'doc_1']

1位: doc_2 score=1.00
2位: doc_3 score=0.00
3位: doc_1 score=0.00
```

質問には入力上の誤記があったが、`doc_2`を正しく1位にできた。

## 確認問題と回答

1. `search_documents` Tool自身は、最終的な自然文の回答を生成しますか？
   - 回答: いいえ
   - 判定: 正解
   - 解説: Toolは検索候補を返し、その候補を根拠にLLMが最終回答を生成する。

2. 検索結果に`source`を含める理由は何ですか？
   - 回答: 未回答
   - 判定: 未回答
   - 解説: 本文の出典文書を追跡し、回答の引用やContext外引用の検証に使う。

3. `doc_1`と`doc_3`のスコアが0.00でも結果に含まれているのはなぜですか？
   - 回答: 参照されたが、そのタイトルが含まれていなかったため
   - 判定: 不正解
   - 解説: `top_k=3`で3件を候補にし、Rerankerが候補3件をすべて評価して返したため。0.00は質問との関連度が低いという評価であり、タイトルの有無が理由ではない。

4. `source: doc_2`は何を意味しますか？
   - 回答: 説明後に理解を確認（OK）
   - 判定: 説明後理解
   - 解説: その検索結果の出典文書が`doc_2`であることを表す。

## 要復習

- `source`は出典文書IDであり、引用追跡とContext照合に使う。
- Toolの`sources`は候補文書一覧であり、最終回答の引用一覧とは分けて考える。
- Rerankerの0.00は、候補から除外されたという意味ではなく、候補内で関連度が低いという意味である。
