# Day 64: 状態機械と純粋な遷移判断

## 学習テーマ

Agentの処理を、State・Node・Edge・終了条件として整理した。

```text
State = Agentが持ち回る情報
Node = 1つの処理
Edge = 次のNodeへの経路
end  = 処理の終了
```

## State

`AgentState`には、質問・分類結果・検索Context・回答・現在のNodeを保存する。

```text
question     ユーザーの質問
route        質問の分類結果
context      検索で見つかった参考情報
answer       最終回答
current_node 現在実行中のNode
```

## NodeとEdge

処理の流れは次の通り。

```text
classify
  ├─ route="search"      → retrieve
  └─ それ以外             → fallback

retrieve
  ├─ contextあり           → generate
  └─ contextなし           → fallback

generate → end
fallback → end
```

`generate`は回答本文を`state.answer`へ保存した後、`end`へ進む。`answer`はStateのフィールドであり、遷移先のNode名ではない。

## 純粋関数

純粋関数は、次の2つを満たす。

1. 同じ入力なら常に同じ結果を返す
2. 外部の状態を変更しない

次の関数は、検索やStateの変更を行わず、入力だけで次のNodeを決めるため純粋関数である。

```python
def choose_next_node(context: str) -> str:
    if context:
        return "generate"

    return "fallback"
```

一方、次の処理は`state.context`を書き換えるため、純粋関数ではない。

```python
state.context = retrieve_context(state.question)
```

検索処理と遷移判断を分けると、検索側とNode遷移側を別々にテストでき、エラーの切り分けがしやすくなる。

## 遷移判断の実装

```python
def choose_after_classify(route: str) -> str:
    if route == "search":
        return "retrieve"

    return "fallback"
```

## 単体テスト

```python
assert choose_after_classify("search") == "retrieve"
assert choose_after_classify("unsupported") == "fallback"
```

関数を直接呼び出し、返り値が期待値と一致するかを`assert`で確認する。

## 要復習

- `answer`はStateのフィールドであり、遷移先は`end`。
- 純粋関数は、入力以外の状態を変更せず、同じ入力に同じ結果を返す。
- `assert`では、未定義の変数を比較するのではなく、テスト対象の関数を呼び出す。
