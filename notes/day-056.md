# Day 56: 引用・未回答の統合

## 学習テーマ

Context Builderで作成した参考情報を使って、回答可能な場合は引用元付きで回答し、回答できない場合は推測せず拒否する処理を統合した。

## 処理の流れ

```text
質問
  ↓
BM25・Vector・RRF・Reranker
  ↓
Context Builder
  ↓
Contextが空かをPythonで確認
  ↓
LLMが回答可能性を判断
  ↓
Structured OutputをPydanticで検証
  ↓
Pythonが引用元をContextと照合
  ↓
回答または拒否
```

## PythonとLLMの役割分担

### Pythonの事前チェック

Contextが空の場合は、LLMを呼び出さずにPythonが拒否する。
参照文書がない状態でLLMに推測させないためである。

```python
if not context_result.context_text.strip():
    return create_refusal(
        reason="回答に使える参考情報がありません。"
    )
```

### LLMによる意味的なチェック

Contextが存在していても、質問の答えが書かれているとは限らない。
LLMには、質問とContextを比較し、答えが見つからなければ`status="refused"`を返すように指示した。

これは、文書が空かどうかではなく、文書の内容が質問に答えているかを意味的に判断する処理である。

### Pydanticによる形式チェック

`GroundedAnswer`で、LLMの出力状態を検証する。

- `answered`の場合、`answer`と`sources`を必須にする
- `refused`の場合、`answer`と`sources`を空にする
- `refused`の場合、`refusal_reason`を必須にする

これにより、`refused`なのに回答本文が入っているような不整合を防ぐ。

### Pythonによる引用元チェック

LLMが返した`sources`が、実際にContextへ渡した文書IDの集合に含まれるかを確認する。

```python
unsupported_source_ids = (
    cited_source_ids - allowed_source_ids
)
```

例えば、Contextに`doc_2`しか存在しないのに、LLMが`doc_99`を引用した場合は不正な引用である。
この場合、Pythonは通常の例外を投げるのではなく、`status="refused"`の結果へ変換する。

```text
LLMがdoc_99を引用
    ↓
PythonがContext外だと検出
    ↓
回答を拒否
```

## 実行結果

### 回答可能ケース

```text
質問: 様式第4号の提出先はどこですか？
status: answered
answer: 様式第4号の提出先は、セキュリティチームです。
sources: ['doc_2']
refusal_reason: None
```

`doc_2`が回答の根拠として使用された。

### 未回答ケース

```text
質問: 経費精算の締め日はいつですか？
status: refused
answer: None
sources: []
```

回答の根拠がないため、推測せず回答を拒否した。
未回答時に`sources`を空にすることで、関係のない文書を誤って引用することを防ぐ。

## 重要な区別

引用元がContextに存在することと、引用内容が回答を本当に裏付けていることは別である。

```text
引用元がContext内に存在するか
  → Pythonのvalidate_sources()

引用内容が回答を裏付けているか
  → Groundedness評価
```

`validate_sources()`は、LLMがContext外の文書を引用していないかを検査する。
しかし、`doc_2`を引用していても、`doc_2`に書かれていない部署名を回答している可能性までは判定しない。

## 確認問題と回答

1. 回答可能な質問で`sources: ['doc_2']`になる意味は何ですか？
   - 回答: その回答の根拠が`doc_2`にある。
   - 判定: 正解。`doc_2`が回答の根拠文書として使用されたことを示す。

2. 未回答ケースで`sources: []`にする理由は何ですか？
   - 回答: 根拠が何もないから。
   - 判定: 正解。根拠のない文書を誤って引用しないためである。

3. `validate_sources()`は何を防いでいますか？
   - 回答: LLMがContextに存在しない文書を引用しない。
   - 判定: 部分正解。PromptでLLMに禁止するだけでなく、Pythonが出力後にContext外の引用を検出し、回答を拒否する。

### 追加問題

Contextに存在する文書が`{"doc_2"}`だけなのに、LLMが` sources=["doc_99"]`を返した場合、Pythonはどうしますか？

- 回答: LLMがContextにはない文書を引用したためエラーになる。
- 判定: 正解。より正確には、通常の例外を投げるのではなく、不正引用を検出して`status="refused"`の結果へ変換する。

## 要復習

- PythonはContextの有無と、引用IDの存在を確定的に検査する。
- LLMはContextの内容が質問に答えているかを意味的に判断する。
- Pydanticは回答・拒否・引用元フィールドの整合性を検証する。
- Context内の文書を引用していても、内容が根拠になっているとは限らない。
