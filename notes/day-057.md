# Day 57: 失敗分類と閾値

## 学習テーマ

RAGの失敗を、検索・生成・引用のどの段階で発生したかに分類した。
また、回答を許可または拒否する閾値を設定し、安全性と回答率のトレードオフを整理した。

## 失敗分類

```text
検索失敗
  └─ 正解文書を検索できない

生成失敗
  └─ 正しいContextがあるのに、LLMが誤回答・推測・不適切な拒否をする

引用失敗
  └─ 回答は生成されたが、引用がない・誤っている・Context外を引用する
```

### Retrieval Failure

回答可能な質問で、正解文書が検索結果に含まれていない状態。

```text
正解文書: doc_2
検索結果: []
```

この場合、LLMへ正しい情報を渡せないため、根本原因は検索失敗である。

### Generation Failure

正しい文書がContextに含まれているにもかかわらず、LLMがContextに基づいて回答できない状態。

```text
正解文書: doc_2
Context: doc_2を含む
生成回答: 参考情報に記載されていません
```

Contextが存在しないのではなく、LLMがContextを使わなかったり、読み間違えたり、誤って拒否したりしている。

### Citation Failure

回答自体は生成されたが、引用元が不正確な状態。

- 引用がない
- 正解文書を引用していない
- Context外の文書を引用している
- 余計な文書まで引用している

## `should_refuse`の意味

`should_refuse=True`は、拒否という行動を取るべきかを示す値であり、成功・失敗そのものではない。

```text
分類                         should_refuse    判定
retrieval_failure            True             失敗
generation_failure           True             失敗
unknown_correct_refusal      True             成功
```

正解文書が存在しない質問では、拒否することが正解である。
一方、正解文書が存在するのに検索や生成に失敗して拒否した場合は、安全な動作ではあるが、タスク結果としては失敗である。

```text
should_refuse = 取るべき行動
failure_type  = その結果が成功か失敗か
```

## 閾値

今回は例として、次の閾値を使用した。

```text
min_reranker_score: 0.70
min_relevance_score: 0.70
```

閾値を低くすると回答数は増えるが、誤回答や根拠の弱い回答が増えやすい。
閾値を高くすると安全性は上がるが、本来回答できる質問まで拒否しやすくなる。

したがって、閾値は固定の正解値ではなく、評価データで次の指標を比較して決める。

- 正答率
- 未回答正解率
- 誤拒否率
- Grounded率
- Relevance

## 実行結果

```text
============================================================
ID: retrieval_failure
分類: retrieval_failure
拒否するか: True
理由: Expected document 'doc_2' not found in retrieved documents: []
============================================================
ID: generation_failure
分類: generation_failure
拒否するか: True
理由: Generated answer is not grounded in the provided context
============================================================
ID: unknown_correct_refusal
分類: expected_no_answer
拒否するか: True
理由: Correctly refused to answer a question with no expected document
```

`unknown_correct_refusal`は、拒否することが正解のため、`should_refuse=True`でも成功扱いになる。

## 確認問題と回答

1. `retrieval_failure`と`generation_failure`の違いは何ですか？
   - 回答: Retrievalは検索Contextにない。GenerationはLLMにContextがない。
   - 判定: 部分正解。Retrievalは正しい文書がContextにない。Generationは正しいContextがあるのに、LLMが誤回答・推測・不適切な拒否をする。

2. `unknown_correct_refusal`が成功扱いになる理由は何ですか？
   - 回答: そもそもその文書がないので、回答を拒否するのが正解。
   - 判定: 正解。

3. 閾値を0.70に固定せず、評価データで調整する必要があるのはなぜですか？
   - 回答: ケースによって閾値は異なる。
   - 判定: 部分正解。ケースや用途によって異なるうえ、閾値を下げた場合の誤回答増加と、上げた場合の誤拒否増加を評価して決める必要がある。

### 追加問題

正解文書がContextに含まれているのに、LLMが「参考情報に記載されていません」と拒否した場合、どの失敗に分類しますか？

- 回答: `generation_failure`
- 判定: 正解。検索は成功しているため、Contextを使って回答できなかった生成段階の失敗である。

## 要復習

- `should_refuse=True`は拒否という行動を示すだけで、成功・失敗を直接示さない。
- 正解文書がない質問を正しく拒否することは成功である。
- 正しいContextがあるのに拒否した場合はGeneration Failureである。
- 閾値は正答率、Grounded率、誤拒否率、未回答正解率のバランスで調整する。
