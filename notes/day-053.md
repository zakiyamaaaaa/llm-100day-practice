# Day 53: Multi-query検索

## 学習テーマ

1つの質問から複数の検索Queryを生成し、各QueryのBM25・Vector検索結果をRRFで統合した。

## 学習した内容

- Day52のQuery Rewriteは、1つの質問を1つのQueryへ変換する。
- Multi-queryでは、元のQueryを残したまま複数の代替Queryを作る。
- 元のQueryを残すことで、LLMのRewriteが不適切でも元の検索結果を失わない。
- QueryごとにBM25検索とVector検索を実行する。
- 各ランキングをRRFへ渡し、複数のランキングで上位に出る文書へ加点する。
- RRFは検索結果に存在しない新しい文書を発見する仕組みではない。
- Multi-queryは必ずBM25を改善するわけではない。正確なTokenが生成されなければBM25は空のままになる。
- Vector検索では表現が異なっていても意味の近さで文書を取得できる。
- Multi-queryの有効性は、Rewrite前後の正解率だけでなく、QueryごとのランキングとRRF統合結果で確認する。

## 実行結果

### `confidential_information`

生成された3つのQueryでBM25はすべて空だった。一方、Vector検索では`doc_1`が次の順位で取得された。

```text
Query 1: doc_1, doc_2, doc_3
Query 2: doc_1, doc_2, doc_3
Query 3: doc_1, doc_3, doc_2
```

`doc_1`が複数のVectorランキングで上位に登場したため、RRFで1位になった。

### `travel_expense`

3つのQueryすべてでVector検索の1位が`doc_3`となり、RRFでも`doc_3`が1位になった。

### 結果の解釈

Multi-queryによってBM25の検索結果が改善したわけではない。今回の結果では、複数のVector検索結果をRRFで統合し、正解文書が安定して上位に来ることを確認した。

## 確認問題と回答

初回問題:

1. Multi-query後もBM25が空だった理由: Queryが文書中の正確なTokenと一致しなかったため。正解。
2. `confidential_information`でRRFが`doc_1`を1位にした理由: 「すべての検索方法で1位」と回答。部分正解。Vectorの順位が1位、1位、2位であり、BM25は空だった点を補足。
3. 今回Multi-queryが役立った処理: Vector検索結果の統合に役立った。正解。

追加問題:

1. Vector順位が1位、1位、2位の文書がRRFで高くなる理由: RRFの`1 / (k + 順位)`を各ランキングで計算して合計した結果、他の文書より合計スコアが高くなった。正解。

## 要復習

- RRFのスコアは各ランキングで加算され、複数のランキングに登場する文書ほど有利になる。
- Multi-queryは候補文書を増やすが、正解を保証しない。
- BM25の失敗はTokenizer・表記揺れ、Vector検索の失敗はEmbedding・データ品質など、検索方式ごとに原因を分けて考える。
