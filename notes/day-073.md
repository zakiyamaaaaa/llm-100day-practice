# Day73：非同期Embedding

## 目的

既存の同期Embedding処理を再利用しながら、独立した複数のEmbedding API呼び出しを非同期で実行し、処理時間と費用への影響を比較する。

## 学習内容

- `async def`を付けるだけでは、同期クライアントの処理は非同期にならない。
- OpenAI APIの非同期呼び出しには`AsyncOpenAI`と`await`を使う。
- 各文書のEmbeddingは他の文書の結果に依存しないため、`asyncio.gather()`で並列実行できる。
- BM25のToken分割や辞書登録のようなローカル計算は、今回の主な非同期化対象ではない。
- 非同期化で待ち時間は短縮できるが、API呼び出し数やToken数は減らないため、費用は自動的には下がらない。
- Day61の「独立処理は並列、依存処理は順次」という判断をEmbedding APIへ適用した。

## 成果物

- `async_embedding_benchmark.py`

処理の構成：

```text
既存の同期Embedding
        ↓ 比較
AsyncOpenAI + asyncio.gather()
```

## 実行結果

文書3件を同じEmbeddingモデルで処理した。

```text
同期処理時間: 3.23秒
非同期処理時間: 0.47秒
時間比: 6.91倍
文書ID一致: True
Embedding次元数一致: True
各方式のAPI呼び出し数: 3回
```

Embedding結果の識別情報とベクトル次元数が一致しているため、方式を変えても結果の構造は維持されている。

## 重要な理解

非同期化は、1回のAPI応答を高速化する技術ではなく、独立した複数のネットワーク処理を同時に待てるようにする技術である。

```text
同期：API A完了 → API B完了 → API C完了
非同期：API A・B・Cを開始 → まとめて待つ
```

費用は呼び出し回数とToken数に依存する。今回のように同じ3文書を各方式で3回ずつEmbeddingした場合、非同期化だけでは費用は減少しない。

## 要復習

- `async def`だけでなく、非同期クライアントと`await`が必要。
- 非同期化の効果は、独立したI/O待ちが複数ある場合に大きい。
- 非同期化とコスト最適化は別の改善軸。
