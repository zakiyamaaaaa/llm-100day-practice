# Day 43: TransformerとToken

## 学習テーマ

Token、Token ID、Embedding、Attention、Context Windowの基本的な関係を、小さな数値例で確認した。

## 学習した内容

- LLMは入力文章をTokenに分割して処理する。
- Tokenは整数のToken IDに変換される。
- TokenはEmbeddingによって数値ベクトルとして表現される。
- Attentionは、Queryと各Keyの関連度を計算し、Valueを重み付きで合成する。
- 内積は、各要素を掛け算してから合計する。
- Attentionの基本式は`softmax(QK^T / √d_k)V`。
- Context Windowは、LLMが一度に扱えるToken数の上限である。

## 実行結果

- Token数: 5
- Context Window上限: 10
- Context Window判定: 範囲内
- Keyとの内積: `[1.0, 0.5, 0.0]`
- Attention重み: `[0.4555, 0.3198, 0.2246]`
- 最終出力: `[5.6783, 4.3217]`

## 発生した問題と原因

最初の実行では、内積計算が次のようになっていた。

```python
left_value + right_value
```

正しくは、掛け算してから合計するため、次の式に修正した。

```python
left_value * right_value
```

修正後、Queryに最も近いKey 1のAttention重みが最大になった。

## 確認問題と回答

1. 内積で`*`を使う理由: 内積は掛け算してから合計するため。正解。
2. 最も強く参照されるKey: Key 1。正解。
3. Context Window超過時の問題: 文章全体の関係を捉えにくくなる。核心は正解。入力の切り捨てやAPIエラーが起きる可能性もある。
