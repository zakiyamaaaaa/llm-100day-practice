# Day 58: Production RAG v1

## 学習テーマ

Day48〜57で作成したRAG部品を、1つの入口から実行できるProduction RAG v1へ統合した。

```text
質問
  ↓
BM25・Vector検索
  ↓
RRF
  ↓
Reranker
  ↓
Context Builder
  ↓
回答または拒否
  ↓
Citation検証
  ↓
Smoke Evaluation
```

## 統合した部品

- `hybrid_rag_pipeline.py`: BM25・Vector・RRF・Reranker
- `context_builder.py`: 重複除去、順位整理、Token上限
- `answer_with_citations.py`: 回答・拒否のStructured Output、sources検証
- `rag_evaluation_dataset.py`: 評価ケースと期待する正解
- `production_rag_v1.py`: 各部品を呼び出すオーケストレーション

新しい検索アルゴリズムを作るのではなく、既存部品の責務を保ったまま、1本の処理として接続した。

## Production RAG v1の設計

### アプリ起動時

`build_retrieval_context()`を一度だけ実行する。
この処理でBM25Indexと文書Embeddingを作成し、複数の質問で再利用する。

質問ごとにContextを作り直すと、同じ文書Embeddingを何度も作成し、API費用と処理時間が増えるためである。

### 質問処理時

`answer_question()`を呼び出すだけで、検索から回答までが実行される。

```text
answer_question()
  ├─ Retriever
  ├─ RRF
  ├─ Reranker
  ├─ Context Builder
  ├─ LLM回答・拒否
  └─ sourcesのContext照合
```

### 評価時

Smoke Testでは、次の最低限の契約を確認した。

回答可能ケース:

```text
status = answered
正解文書がsourcesに含まれる
```

未回答ケース:

```text
status = refused
sources = []
```

Smoke TestはPipelineが接続されているかを確認するものであり、回答本文の意味的な正しさ、Groundedness、詳細なCitation品質、latencyや費用までは評価しない。

## Groundedと正解判定の違い

Groundedは、回答の根拠がContext内に存在するかを確認する。
正解判定は、質問に対する答えが正解回答と一致するかを確認する。

そのため、次のケースは発生し得る。

```text
Context:
doc_1: 旧文書では提出先は法務部
doc_2: 最新版では提出先はセキュリティチーム

LLM回答: 法務部です。[doc_1]
```

この場合、回答は`doc_1`というContext内の根拠を持つため、定義によっては`Grounded=True`になる。
しかし、最新版や期待する正解がセキュリティチームなら、正解判定は`False`になる。

したがって、Groundedだけで回答の正しさを判断してはいけない。

```text
Grounded:
  Contextに基づいているか

Relevance:
  質問への回答として適切か

正解判定:
  正解回答と同じ意味か

Citation:
  正しい文書を引用しているか
```

## 確認問題と回答

1. Smoke TestとGeneration評価の違いは何ですか？
   - 回答: 未回答。
   - 解説: Smoke TestはPipelineの接続、status、sourcesの最低限の契約を確認する。Generation評価はContextに基づいているか、質問に適切に答えているか、正解回答と同じ意味かを評価する。

2. `build_retrieval_context()`をアプリ起動時に一度だけ実行する理由は何ですか？
   - 回答: 未回答。
   - 解説: BM25Indexと文書Embeddingを毎回作り直すと、同じ文書EmbeddingのAPI費用と処理時間が繰り返し発生するため。

3. 今回の`2/2 (100%)`だけでは、何を証明できませんか？
   - 回答: 未回答ケース。
   - 判定: 部分正解。未回答ケースに加え、意味的な回答の正しさ、Groundedness、Citation品質、latency、API費用までは証明できない。

4. Smoke TestがPASSでも、LLMの回答本文が間違っていた場合、どの評価で検出しますか？
   - 回答: Grounded評価。
   - 判定: 部分正解。Grounded評価は根拠性を確認する。回答内容の正しさは、Generationの正解判定とRelevanceも必要である。

5. `build_retrieval_context()`を質問ごとに実行すると、どのような問題が起きますか？
   - 回答: 同じ文書Embeddingを何度も作る、コストがかさむ、API費用が増える。
   - 判定: 正解。加えて、処理時間とレイテンシも増加する。

6. Contextに「提出先はセキュリティチーム」と書かれていて、LLMが「提出先はセキュリティチーム」と答えた場合、Groundedと正解判定はどうなりますか？
   - 回答: Grounded=True、正解判定=False。
   - 判定: 問題文との対応が不明確だったため、条件を整理した。回答もセキュリティチームなら、通常はGrounded=True、正解判定=Trueである。Grounded=True・正解判定=Falseは、Context内に根拠はあるが、旧文書・競合文書・質問の期待と異なる場合に成立する。

## 要復習

- Smoke Testは統合確認であり、回答品質全体の評価ではない。
- `build_retrieval_context()`はアプリ起動時に一度だけ実行し、複数質問で再利用する。
- `Grounded=True`でも、正解判定がFalseになる場合がある。
- Grounded、Relevance、正解判定、Citationを分離して評価する。
- 未回答ケースの拒否は、正解文書がない場合には成功である。
