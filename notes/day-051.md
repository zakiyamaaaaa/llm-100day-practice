# Day 51: 更新・削除・重複排除

## 学習テーマ

Metadata付きIngestを発展させ、Content Hashを使った重複排除、文書更新、削除を実装した。

## 学習した内容

- Content Hashは文書本文から作る指紋で、同じ内容なら同じHashになる。
- 同じHashの文書を再Ingestしないことで、重複登録と不要なEmbedding API呼び出しを防げる。
- `upsert`は追加・更新を行うが、不要になった古いChunkを自動削除するとは限らない。
- 文書更新時は、同じ`source`の古いChunkを削除してから新しいChunkを登録する。
- 古いChunkを残すと、古い情報と新しい情報が両方検索対象になり、RAGが古い情報を参照する可能性がある。
- `docs`フォルダから消えたsourceをMetadataから特定し、そのChunkを削除できる。
- 2回目の同期で`unchanged`や`deleted_chunks: 0`になることも、冪等な処理の確認になる。
- `query()`は類似検索用、`get()`はMetadata条件に一致するデータ取得用である。

## 実行結果

### 新規登録と重複排除

```text
1回目: {'inserted': 2, 'updated': 0, 'unchanged': 0, 'deleted_chunks': 0}
2回目: {'inserted': 0, 'updated': 0, 'unchanged': 2, 'deleted_chunks': 0}
```

2回目は同じContent Hashを検出し、再登録をスキップできた。

### 文書更新

```text
1回目: {'inserted': 0, 'updated': 1, 'unchanged': 1, 'deleted_chunks': 0}
2回目: {'inserted': 0, 'updated': 0, 'unchanged': 2, 'deleted_chunks': 0}
```

変更した文書だけ更新され、2回目は変更なしとしてスキップされた。

### 文書削除

```text
1回目: {'inserted': 0, 'updated': 0, 'unchanged': 1, 'deleted_chunks': 1}
2回目: {'inserted': 0, 'updated': 0, 'unchanged': 1, 'deleted_chunks': 0}
```

削除したファイルのChunkが1回目に削除され、2回目は削除対象なしとなった。

## 確認問題と回答

初回問題:

1. 同じ文書を2回Ingestしても重複しない理由: 文書Hashで同じものと判断し、2回目のIngestをやめたため。正解。
2. 更新時に古いChunkを削除する理由: 初回はHashの一意性に言及。部分正解。古い情報と新しい情報が同時に検索対象になることが主な問題だと補足。
3. 削除処理の2回目が`deleted_chunks: 0`になる理由: 1回目に対象Chunkを削除済みだから。正解。

追加問題:

1. 古いChunkを削除せず新しいChunkだけ登録した場合の問題: 古い情報と新しい情報が両方検索対象になる。正解。

## 要復習

- Hashの一意性ではなく、古い情報が検索対象に残ることが更新時の主な問題である。
- `upsert`と削除は別の処理であり、同期処理では両方を設計する。
- 冪等性は、同じ処理を複数回実行しても不要な重複や追加変更が発生しない性質である。
