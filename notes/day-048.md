# Day 48: BM25品質監査

## 学習テーマ

Day32で実装したBM25の数式を監査し、標準的な式へ修正した。その後、修正前後で検索スコアと評価指標を比較した。

## 学習した内容

- BM25は、Query tokenごとのIDFと、文書内のterm frequencyを使って関連度を計算する。
- 文書の長さが平均より長い場合、length normalizationによってスコアを調整する。
- 標準的なBM25の分子は`term_frequency * (k1 + 1.0)`である。
- 標準的なBM25の分母は`term_frequency + k1 * length_normalizer`である。
- 数式を修正しても、検索順位が変わらなければHit@kやMRRは変わらない。
- スコアの変化と順位・評価指標の変化は分けて確認する必要がある。
- `confidential_information`と`travel_expense`が検索できない原因は、BM25式ではなくTokenizerによるtoken不一致である。

## 修正内容

修正前:

```python
numerator = term_frequency + (self.k1 + 1.0)
denominator = term_frequency + self.k1 + length_normalizer
```

修正後:

```python
numerator = term_frequency * (self.k1 + 1.0)
denominator = term_frequency + self.k1 * length_normalizer
```

## 実行結果

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| `doc_2`「様式第4号」のスコア | 1.0501 | 0.9874 |
| `doc_2`「社外PC」のスコア | 1.8485 | 1.7382 |
| Hit@1 | 66.67% | 66.67% |
| Hit@3 | 66.67% | 66.67% |
| MRR | 0.6667 | 0.6667 |
| 未回答正解率 | 100.00% | 100.00% |

修正後も正解文書の順位は変わらなかった。数式の修正によってスコアは変化したが、今回の小規模な評価データでは順位に影響しなかった。

## 確認問題と回答

1. BM25の正しい分子と分母: 分子は`term_frequency * (self.k1 + 1.0)`、分母は`term_frequency + self.k1 * length_normalizer`。正解。
2. スコアが変わってもHit@1やMRRが変わらない理由: 順位が変わらなかったため。正解。
3. `confidential_information`が検索できない理由: 文書とQueryが同じtokenに分割されず、単語の一致が起きなかったため。正解。

## 要復習

- 数式の正しさと、検索順位・評価指標の変化は別々に確認する。
- BM25で検索できない場合、数式だけでなくTokenizer、表記揺れ、Query Rewriteも確認する。
